# 제품 정의서: 회계 기반 고급 가계부

**비전**: "다음 달이 아니라 6개월 후를 보여주는 가계부"

---

## 1. 근본 문제

가계부는 과거를 기록할 뿐, **미래를 보여주지 못한다**.

월급은 매달 25일에 들어오고, 보험료는 매년 1월에 나가고, 부조금은 언젠가 반드시 발생한다. 이런 것들은 모두 어느 정도 예측 가능하다. 그런데 기존 가계부에서 "6개월 후 내 통장에 얼마가 있을까?"라는 질문에 답할 수 있는가? 없다.

왜 못하는가? 가계부가 기록하는 데이터 자체가 **예측에 쓸 수 없는 형태**이기 때문이다.

### 증상 1: 월별 데이터가 왜곡되어 있다

자동차보험 연납 42만원을 1월에 내면, 기존 가계부에서 1월 지출은 42만원이 뻥튀기된다. 2~12월은 보험비가 0원이다. 이 데이터로 "다음 달 지출이 얼마일까?"를 예측하면? 1월 기준이면 과대, 2월 기준이면 과소. **현금이 오간 시점**으로 기록하기 때문에 **비용이 실제로 발생하는 시점**이 왜곡된다.

### 증상 2: 돈의 목적을 알 수 없다

"쿠팡 35,000원"이라는 기록에서 알 수 있는 건 소비처뿐이다. 요리 재료 15,000원 + 칼 12,000원 + 세제 8,000원이었다는 것은 알 수 없다. 더 중요한 건, 같은 "생활용품"이라도 **요리를 위한 것인지 청소를 위한 것인지** 구분이 안 된다. 목적을 모르면 "다음 달 요리에 얼마를 쓸까?"를 예측할 수 없다.

### 증상 3: 이미 아는 미래가 반영되지 않는다

급여 350만원이 매월 25일에 들어온다는 것, 월세 70만원이 매월 1일에 나간다는 것, 하반기 성과급 150만원이 7월에 있다는 것 — 이 모든 것을 사용자는 이미 알고 있다. 하지만 기존 가계부는 이것을 "미래 잔액 예측"에 반영할 수단이 없다.

### 증상 4: 불확실하지만 확실한 지출이 무시된다

부조금은 **언제** 필요할지 모르지만 **반드시** 필요해진다. 긴급 수리비도 마찬가지다. 이런 지출은 예측 불가능하므로 기존 가계부는 무시한다. 하지만 무시한다고 없어지는 게 아니다. 어느 날 갑자기 예측 못한 지출이 터져서 "왜 돈이 없지?"가 된다.

## 2. 설계: 문제에서 예측까지

이 제품의 모든 설계는 하나의 목표를 향한 논리적 경로다: **"6개월 후 내 통장에 얼마가 있을까?"에 답하기.**

### 2.1 "정확한 예측을 하려면 → 정확한 월별 데이터가 필요하다"

예측의 정확도는 입력 데이터의 정확도에 비례한다. "다음 달 지출이 얼마일까?"를 과거 3개월 평균으로 예측한다면, 그 3개월의 데이터가 정확해야 한다.

**→ 설계 결정: 발생주의 회계 도입**

현금이 오간 시점이 아니라, **경제적 사건이 발생한 시점**에 기록한다.

| 상황 | 현금주의 (기존) | 발생주의 (이 제품) |
|------|--------------|------------------|
| 보험료 42만원 1월 연납 | 1월: -42만, 2~12월: 0 | 매월: -3.5만 × 12개월 |
| TV 100만원 카드 결제 | 카드 결제일에 -100만 | 구매 시 자산 등록 + 매월 감가상각 |
| 3월에 사용한 카드 | 4월 결제일에 지출 | 3월에 비용 인식 |

이렇게 하면 **각 월의 비용이 실제 경제적 사건을 반영**하고, 이 데이터로 미래를 예측하면 훨씬 정확해진다.

발생주의가 필요로 하는 것:
- **선불비용 배분**: 일시납을 월별로 나누어 비용 인식
- **감가상각**: 고가 물건의 가치를 내용연수에 걸쳐 비용 인식
- **카드 미결제 추적**: 사용 시점에 비용 인식, 결제는 별도 처리

**자산/비용 구분 기준**: 얼마 이상이면 자산(감가상각 대상)이고 얼마 미만이면 즉시 비용인가? → 가계 지출 규모의 10%를 기준으로 하되 사용자가 조정 가능. 기업회계에서도 회사 규모에 따라 이 기준(중요성 기준)이 다른 것과 같은 원리.

### 2.2 "발생주의를 정확히 하려면 → 돈의 위치와 목적을 분리해야 한다"

"삼성카드로 마트에서 3만5천원"이라는 거래를 발생주의로 기록하려면, 두 가지를 동시에 알아야 한다:

- **Where**: 삼성카드 미결제(부채)가 3만5천원 증가
- **Why**: 요리 목적으로 1만5천원, 청소 목적으로 8천원, 요리 도구로 1만2천원

이 두 축을 분리하지 않으면 복식부기가 성립하지 않고, 복식부기 없이는 순자산 추적이 부정확해진다.

**→ 설계 결정: 계정 체계를 두 축으로 분리**

**재정 계정 (Where)** — 돈이 어디에 있는가:
- 자산: 현금성자산(추상 버킷), 선불비용, 고정자산
- 부채: 삼성카드 미결제, 대출 잔액, 준비금

**목적 계정 (Why)** — 왜 돈이 오갔는가:
- 지출: 요리, 교통, 주거, 건강...
- 수입: 근로소득, 부수입, 투자수익...

**왜 목적(Why)을 기업회계처럼 품목(What)으로 분류하지 않는가?**

기업회계는 "원재료비, 인건비, 감가상각비"처럼 **성격별(by nature)**로 분류한다. 이유: 외부 감사인이 객관적으로 검증해야 하므로. 하지만 가계부에는 외부 감사가 없다. 분류자 = 사용자 본인이므로, 주관적 판단이 곧 정답이다.

그리고 목적별 분류가 **예측에 유리**하다:
- 의사결정이 목적 단위로 이루어짐: "식료품을 줄이자"가 아니라 "외식 대신 직접 요리하자"
- 예측이 안정적: 품목 구성이 바뀌어도(손질된 재료 vs 날것+도구) 목적별 총액은 비교적 안정적
- 활동의 총비용이 보임: "요리에 재료+도구+가스비 합쳐서 월 35만원"

**자산 계정의 특수한 설계**: 자산은 **추상적 버킷**으로 운영한다. "국민은행 500만 + 카카오뱅크 300만"이 아니라 "현금성자산 800만". 실제 계좌별 잔액은 별도로 추적하고, 월 결산 시 총액 일치만 확인.

**부채 계정은 실제 분리**: 삼성카드와 현대카드는 결제일이 다르므로, 현금흐름 예측에 직접 영향. 따라서 카드/대출별로 분리 추적.

**복식부기는 내부 구현**: 사용자는 "삼성카드로 요리 재료 1만5천원"이라고 입력할 뿐이다. 시스템이 내부적으로 "Dr. 요리(비용) / Cr. 삼성카드미결제(부채)"라는 복식부기 분개를 자동 생성한다. 사용자는 차변/대변을 알 필요 없다.

### 2.3 "예측 가능한 미래를 반영하려면 → 패턴을 등록해야 한다"

발생주의로 과거 데이터가 정확해졌다. 이제 이걸로 미래를 예측할 수 있다. 하지만 과거 데이터만으로는 부족하다. **이미 알고 있는 미래**를 명시적으로 반영해야 한다.

**→ 설계 결정: 현금흐름을 4가지 유형으로 분류하고, 각각 다른 예측 방식 적용**

| 유형 | 성격 | 예시 | 예측 방식 |
|------|------|------|----------|
| **고정 반복** | 금액/주기 확정 | 급여, 월세, 구독료 | 사용자 등록 → 확정 반영 |
| **변동 반복** | 매월 발생, 금액 변동 | 식비, 교통비 | 과거 데이터 기반 통계 예측 |
| **예정 비반복** | 시점 확정, 일회성 | 보너스, 연납 보험료 | 사용자 등록 → 해당 월 반영 |
| **불확실 발생** | 시점/금액 불확실 | 부조금, 긴급 수리 | → 다음 절(2.4)에서 해결 |

**고정 반복**과 **예정 비반복**은 사용자가 미리 등록하면 된다. "급여 350만원, 매월 25일"을 한 번 등록하면 미래 6개월의 급여가 자동으로 예측에 반영된다.

**변동 반복**은 과거 데이터에서 통계적으로 예측한다. 이상치(일시적으로 큰 지출)를 제거하고, 최근 데이터에 높은 가중치를 두는 지수가중이동평균(EMA)으로 "다음 달 식비"를 추정한다.

**선불비용**: 고정 반복이나 예정 비반복 중 "일시불 납부이지만 여러 월에 걸친 비용"인 경우, 발생주의에 따라 월별 배분한다. 예: 연간 보험료 42만원 → 매월 3.5만원 비용.

### 2.4 "예측 불가능하지만 확실한 미래를 반영하려면 → 준비금이 필요하다"

4유형 중 마지막: 부조금, 긴급 수리비 같은 "언제 터질지 모르지만 반드시 터지는" 지출. 이것을 무시하면 예측이 낙관적으로 치우친다.

**→ 설계 결정: 준비금 계정**

기업회계의 "충당부채(provision)"를 가계부에 맞게 변형.

**작동 방식**:
1. 사용자가 "부조금 준비금, 월 10만원"을 등록
2. 매월 회계상으로 10만원이 적립됨 (실제 돈 이동 없음 — 가상 적립)
3. 현금흐름 예측에서 이 10만원이 **지출로 반영**됨 (보수적 예측)
4. 실제 부조금을 낼 때 준비금에서 차감

**왜 "지출로 반영"하는가?** 이 돈은 미래에 반드시 나갈 돈이므로, "쓸 수 있는 돈"으로 계산하면 안 된다. "6개월 후 통장에 얼마가 있을까?"에서 준비금 적립분을 빼야 현실적인 예측이 된다.

### 2.5 "이 모든 것을 합치면 → 하나의 예측이 된다"

지금까지의 설계를 합치면:

```
미래 N월의 예상 잔액
= 현재 현금성자산 잔액
+ Σ (고정 반복 수입 - 고정 반복 지출)     ← 등록된 확정 값
+ Σ (변동 반복 수입 - 변동 반복 지출)     ← EMA 통계 예측
+ Σ (예정 비반복 수입 - 예정 비반복 지출) ← 등록된 일회성
- Σ (준비금 월 적립액)                     ← 보수적 안전마진
```

이것이 **"6개월 후 내 통장에 얼마가 있을까?"**에 대한 답이다.

동시에, 순자산의 미래 추이도 계산된다:
```
미래 N월의 순자산 = 현재 순자산 + Σ (월별 순저축)
```

**두 개의 예측 그래프**:
- **현금흐름 예측** (현금성자산 기준): "돈이 부족해질까?"
- **순자산 추이** (자산-부채 기준): "재산이 늘고 있나?"

## 3. 제품이 보여주는 것

위 설계가 사용자에게 어떻게 보이는가.

### 3.1 대시보드: 현재 + 미래

앱을 열면 가장 먼저 보이는 화면.

**이번 달 요약** (발생주의 기준):
- 이번 달 수입
- 이번 달 비용 (감가상각 + 선불비용 배분 + 준비금 적립 포함)
- 순저축 또는 순소비
- 현재 순자산

**예측 그래프**:
- 현금흐름 예측 (6개월 / 12개월 전환)
- 순자산 추이 (과거 + 미래 연결)

**예측 드릴다운**: 그래프의 특정 월을 클릭하면 해당 월의 예측이 4유형별로 분해되어 표시.

```
2026년 7월 예측
───────────────
고정 반복
  + 급여           +3,500,000
  - 월세             -700,000
  - 넷플릭스          -17,000
  소계            +2,783,000

변동 반복 (통계 예측)
  - 요리(식비)       -240,000
  - 외식             -180,000
  - 교통              -65,000
  소계               -485,000

예정 비반복
  + 하반기 성과급  +1,500,000
  소계            +1,500,000

준비금 적립
  - 부조금            -100,000
  - 의료비             -50,000
  소계               -150,000

월 합계           +3,648,000
```

### 3.2 보고서: 과거 분석

과거 데이터를 정리하여 보여주는 3가지 보고서. 모두 월 선택 가능.

**월간 손익** (P&L): "이번 달 얼마나 벌고 썼나?"
- 수입: 목적별 내역
- 비용: 목적별 내역 (감가상각/선불비용/준비금 포함)
- 순저축/순소비

**재산 현황** (B/S): "지금 순자산이 얼마인가?"
- 현금성자산 (유동)
- 선불비용 잔액
- 고정자산 (장부가)
- 부채 (카드별 미결제, 대출, 준비금)
- 순자산

**현금흐름표** (C/F): "실제 돈이 얼마나 오고 갔나?"
- 현금 유입 / 유출 (현금주의 기준)
- 발생주의 손익과의 차이를 이해하는 데 활용

### 3.3 월 결산: 현실과 회계의 대사

월 1회, 사용자가 실제 은행/카드 잔액을 입력하면 회계상 잔액과 비교. 차이가 있으면 조정 분개를 제안. 이것으로 "내가 빠뜨린 거래가 있는가?"를 확인한다.

|------|------|------|
| 1 | 월 소득/지출 범위 입력 | 자산/비용 구분 기준액 산정 |
| 2 | 결제 수단 등록 (카드, 계좌 등) | 거래 입력 시 "어떻게 결제했는지" 선택지 |
| 3 | 각 계정의 현재 잔액 입력 | 가계부 시작점 설정 |
| 4 | 계정/카테고리 확인 | 기본 목적 계정 템플릿 커스터마이징 |
| 5 | AI API 키 (선택) | 영수증 자동 인식 활성화 |

### 4.2 일상: 거래 입력

**지출**: 날짜 + 설명 + 결제수단 + 항목(금액, 목적, 품목). 한 결제를 여러 항목으로 분리 가능.
**수입**: 날짜 + 설명 + 입금계정 + 수입목적 + 금액.
**이체**: 날짜 + 설명 + 출금계정 → 입금계정 + 금액. (카드대금 결제, 계좌이체 등)

입력 방법: 수동 입력 또는 영수증 사진 → AI 자동 인식 → 확인/수정 후 저장.

기준액 초과 지출 시 "자산으로 등록할까요?" 제안.

### 4.3 관리

- **반복/예정 거래**: 급여, 월세, 구독료 등 등록/수정/삭제
- **준비금**: 생성, 적립액 변경, 비활성화
- **자산**: 목록 조회(현재 장부가), 처분
- **계정/카테고리**: 목적 계정 + 품목 카테고리 추가/수정/삭제
- **결제 수단**: 추가/삭제
- **설정**: 자산/비용 기준액, AI 키, 예측 기간 (6/12개월)
- **데이터 내보내기**: CSV

### 4.4 분석

- **대시보드**: 이번 달 요약 + 예측 그래프 (매일 확인)
- **보고서**: 월별 손익/재산/현금흐름 분석 (월 1회)
- **결산**: 실제 잔액 대사 (월 1회)

## 5. 부가 사항

### 인증
Google 소셜 로그인.

### AI 영수증 인식
사용자 본인의 AI API 키로 동작. 멀티모달 LLM이 영수증 이미지에서 항목/금액을 추출하고, 목적 계정까지 추론하여 제안.

### UI
반응형 (모바일 대응), 시스템 다크/라이트 모드, 회계 용어 그대로 사용.

### 데이터 원칙
- 실시간 계산 (마감 없음, 항상 최신)
- 과거 데이터 자유 수정 (수정 시 이후 월 자동 재계산)
- Rounding: 매월 floor(총액/개월수), 마지막 월에 잔여액 조정
